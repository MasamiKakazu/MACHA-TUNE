# MACHA-TUNE 初回リリース要件定義書
レビュー案 v0.5 ／ 2026年11月22日

## 目的と合意状況
「新しい『好きな曲』と出会う」。診断する人が自分の好みとおすすめ曲をSlackに投稿し、読み手が興味を持った曲を普段の配信サービスで聴けることを目指す。

**本人の方針**　個人の音楽タイプ診断、おすすめ曲のSlack共有、各音楽サービスへの移動を初回の中心にする。友達追加、ペアの紐づけ、相性比較は対象外。スマートフォンでの使いやすさを重視する。

**確定した曲数**　本人が1曲または3曲を選んで共有する。

**以下はレビュー用の具体案**　6問・4タイプ、共有期限などは変更できる。登録する曲は本人の選曲。診断結果を使った自動選曲は初回対象外。

## 1　診断で聞くこと
1画面に1問、単一選択。進捗を「2 / 6」と表示し、最後まで前の回答を直せる。各行の選択肢は、対応する列のタイプに1点。

| 質問 | 歌詞 | メロディー | リズム | 音の雰囲気 |
| --- | --- | --- | --- | --- |
| 初めて聴く曲、最初に耳に残るのは？ | 印象的な一言 | サビの旋律 | ドラムやベースの刻み | 声や楽器の響き |
| もう一度再生したくなるのは？ | 歌詞の意味を確かめたいとき | 口ずさみたいフレーズがあるとき | あのビートにもう一度乗りたいとき | 曲の空気に浸りたいとき |
| 人にすすめるなら、どこを聴いてほしい？ | 自分に刺さった言葉 | サビに入る瞬間の音の流れ | 思わず体が動くところ | イントロで景色が浮かぶところ |
| 歌詞のない曲を聴くときは？ | 曲に合いそうな物語を想像する | 主旋律を追いかける | 拍をとる | 楽器の音色に耳を澄ます |
| ライブで一番楽しみなのは？ | 好きな歌詞を生で聴く瞬間 | みんなでサビを歌う瞬間 | 会場全体で手拍子する瞬間 | 音に包まれる瞬間 |
| 聴き終わったあとに残るのは？ | 自分に重なる言葉 | 頭の中で流れる旋律 | 自然と刻んでしまうテンポ | その曲が連れてきた気分 |

最多得点のタイプを採用。同点なら、1問目から順に回答を見て、同点候補のうち最初に選んだタイプを採用する。例えば歌詞とリズムが各3点で、最初の回答がリズムならリズムを表示。曲の登録内容は採点に使わない。

| 結果名 | 表示する説明 |
| --- | --- |
| 言葉に惹かれるタイプ | 一言の歌詞や、曲の中にある物語が心に残る人。 |
| 口ずさみたいメロディー派 | 気づけばサビを歌っている。旋律が好きな曲への入り口になる人。 |
| ビートに乗るタイプ | 手拍子したくなるテンポや、体に響くリズムが好きな人。 |
| 音の世界に浸るタイプ | 声の質感や楽器の響きから、曲の景色を楽しむ人。 |

## 2　おすすめ曲の登録
「ここ最近で一番アツい曲」「元気を出したいとき」「落ち着きたいとき」「つい歌いたくなるとき」「ずっと好きな曲」をお題とする。曲入力の最初に「1曲をシェア」「3曲をシェア」から選ぶ。5つから、1曲なら1テーマ、3曲なら異なる3テーマを選び、選んだテーマに1曲ずつ入力する。共有前は切り替え可能。3曲から1曲に切り替えるときは掲載するお題を選び、ほかのお題の入力は下書きに残す。各お題の下に入力例を置く。曲名・アーティスト名は各1〜100文字、前後の空白を除いて判定。同じ曲を複数のお題に選べる。配信リンクはサービスごとに任意で、入力欄は折りたたむ。表示名は任意で30文字以内。未入力なら名前欄を省く。エラーは該当欄の横に表示し、入力済みの内容を保持する。

## 3　結果とSlack共有
結果画面は「タイプ名 → 説明 → お題順の曲カード（1枚または3枚）」。自分の結果を見るまで公開は任意。投稿者が表示内容と「リンクを知っている人が閲覧できます」の案内を確認し、「Slack用の投稿文をコピー」を押すとURLを発行する。コピー例は「音楽タイプは『ビートに乗るタイプ』でした。私のおすすめ曲はこちら！ ［共有URL］」。投稿先と送信は本人がSlackで選ぶ。

共有ページはログイン・診断回答なしで開ける。公開項目は任意の表示名、タイプ名、説明、お題、曲名、アーティスト名、配信リンク。Slackのリンクプレビューにはサービス名と共通説明を使う。コピーできない場合は選択可能な投稿文とURLを表示する。二度押し・通信失敗後の再試行で同じ共有が重複作成されないこと。

## 4　配信先への移動
Spotify、Apple Music、YouTube Musicを曲ごとに選べる。有効な曲リンクがあれば「Spotifyで開く」、省略時は「Spotifyで検索」のように表示。検索語は曲名とアーティスト名の組み合わせ。入力リンクは選択サービスのHTTPS楽曲URLとして検証し、エラー時には修正または省略を案内する。検索先が曲を扱っていない場合も、戻って別サービスを選べる。配信先ごとの検索URL・アプリへの引き渡しは試作で確認し、検索画面へ直接渡せない場合は検索語のコピーとサービスを開く操作を用意する。

## 5　保存・取り消し
入力中の回答は同じタブで前の画面へ戻っても保持。共有時には公開用の結果と選んだ1曲または3曲をひとまとまりで保存し、個々の回答は共有データに保存しない。リンクの有効期間は発行から30日を仮案とし、期限を投稿者に表示。本人用の管理リンクから取り消せる。管理リンクは投稿文に含めない。取り消した時点または期限到来時点で閲覧を停止し、公開内容は24時間以内に削除する案。コピー済みのSlack投稿はアプリ側の削除対象外。

## 6　完成と判断する条件
| 試す場面 | 合格条件 |
| --- | --- |
| 診断の途中で戻る | 回答が残り、修正後の6回答で判定される。同点の場合も結果が一意に決まる |
| 配信リンクがひとつもない | 曲名とアーティスト名を選択した曲数分入れると結果を表示でき、全曲で検索手段を選べる |
| 自分で結果を楽しむ | Slackへの投稿や他人の操作を待たずに結果を確認できる |
| 曲数を切り替える | 3曲から1曲へ切り替えると選んだ1曲だけが共有される。3曲を選んで2曲だけ入力した場合は未入力のお題を案内する |
| Slackで読む | 別端末でURLを開いて、ログインなしで投稿者と同じタイプ・選択した1曲または3曲を確認できる |
| 曲を聴く | 3サービスそれぞれで、登録済みURLを開く場合と未登録の曲を探す場合をスマートフォンで確認できる |
| 失敗から戻る | コピー不可なら手動コピー、発行失敗なら入力を維持して再試行できる |
| 取り消し・期限切れ | 閲覧URLから結果が消え、案内とトップへの導線が表示される |

## 7　試作で優先して決め直すこと
1曲と3曲の両方を試し、切り替え時に掲載する曲が分かるかを確かめる。さらに、6問を答えた本人がタイプ名に納得できるか、読み手が説明なしで聴きたい曲にたどり着けるかを観察する。採用した質問・判定・保存期間は基本設計書にも反映する。

## 8　登録時に見るおすすめ履歴

おすすめ曲の登録画面にだけ、ログイン不要の個人用履歴を表示する。共有リンクを発行した過去の曲を1曲ずつ縦線でつなぎ、上に新しい曲、下に古い曲を置く。各項目には曲名、アーティスト名、選んだテーマ、リンク作成日を表示する。日付は本人がSlackに投稿した日時とは区別する。

| 履歴の曲数 | 登録画面での動き |
| --- | --- |
| 0曲 | 履歴欄を省き、すぐ曲を入力できる |
| 1〜2曲 | すべて表示する |
| 3曲以上 | 最新2曲を表示。「過去に共有した曲を表示する」を押すと、その下に残りの全曲を展開する。「閉じる」で最新2曲に戻す |

展開と折りたたみは同じ画面内で行い、入力中の曲や選択したテーマを保持する。3曲で共有した記録は3項目として数える。共有ページとトップ・結果画面にはツリーを出さない。履歴は同じ端末・ブラウザに保存し、端末間の同期は行わない。
履歴は各曲の登録内容を当時のまま保持し、公開URLの有効期間が終わってもこのブラウザで振り返れる。端末履歴の個別削除と共有リンクの取り消しは別々に操作できる。
